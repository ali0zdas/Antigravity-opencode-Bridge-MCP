# /opencode — OpenCode Subagent Task Delegation

Execute this workflow whenever the user invokes the `/opencode` slash command or requests task delegation to OpenCode.

---

## 1. Input Analysis & Argument Parsing

Analyze the user's input following the `/opencode` command:

1. **Extract Task Details**: Identify the core coding objective, target files, acceptance criteria, and constraints.
2. **Detect Overrides**: Check if the user specified any of the following parameters inline:
   - `provider`: (e.g., `opencode`, `openrouter`, `nvidia`, `ollama`)
   - `model`: (e.g., `deepseek-v4.1-flash-free`, `claude-3-7-sonnet`, `deepseek-r1`)
   - `effort` or `variant`: (`default`, `low`, `high`, `max`)
   - `session_id`: (for continuing an active session)
   - Flags like `--default` or keywords like `use default`

---

## 2. Model & Effort Confirmation Gate

Follow the interactive selection protocol strictly:

### Scenario A: Parameters Are Provided or User Requested "Default"
If the user provided the model/effort, included `--default`, or stated "use default":
- Do **NOT** ask redundant questions.
- Immediately proceed to **Step 3 (Dispatch Task)** with those parameters.

### Scenario B: Parameters Are Missing
If the user only provided a task description without specifying provider, model, or effort:
- **Do not guess or assume silently**.
- Respond with this concise prompt:

> "I am ready to delegate this task to an OpenCode subagent.
> Which **provider**, **model**, and **reasoning effort** (`low`, `high`, `max`, `default`) would you like to use?
> *(Reply **'default'** to use **`opencode / deepseek-v4.1-flash-free (default effort)`**)*"

- Await the user's reply. Once the user replies (e.g., "default", "use default", or specifies custom parameters), proceed directly to **Step 3**.

---

## 3. Dispatch Task via MCP

Invoke the `opencode_delegate_task` tool with the resolved parameters:

```json
{
  "prompt": "<full task description including context, file paths, and verification rules>",
  "provider": "<specified_provider | 'opencode'>",
  "model": "<specified_model | 'deepseek-v4.1-flash-free'>",
  "effort": "<specified_effort | 'default'>",
  "session_id": "<existing_session_id_if_multi_turn | null>",
  "auto_approve": true
}
```

> [!NOTE]
> The `agy-opencode-bridge-mcp` automatically detects and starts `opencode serve` in the background if it is not already running. There is no need to prompt the user to start a server manually.

---

## 4. Multi-Turn Session Handling

1. Capture the `session_id` returned in the tool response.
2. If the user provides feedback, requests revisions, or continues work in the next turn, reuse `session_id` to maintain continuous context within OpenCode.

---

## 5. Result Verification & Presentation

1. Examine the diffs and files generated by the OpenCode subagent.
2. Run any project-specific validation commands (e.g., test suite or linter) if requested.
3. Present a clear, concise summary of changes to the user.
4. **Git Safety Rule**: Remind the user of changes staged or created. Do **NEVER** run `git commit` or `git push` without explicit user permission.
